# Задача на ближайшее будущее: подписка помимо кредитов

Статус: **задокументировано 31.07.2026 по поручению основателя, решения не приняты.**
Это фиксация задачи и развилок, не спецификация. Ничего не строить до явного «го».

## Формулировка

Сервис должен уметь работать не только по кредитам (разовые паки, `docs/credits-economy.md`),
но и по подписке. Кредиты остаются: подписка — второй рельс поверх той же экономики,
не замена.

## Зачем (гипотезы, проверить до строительства)

- Каталог из 19+ тестов с разборами по 95 кр — естественная «библиотека», к которой
  возвращаются; подписка монетизирует возвращаемость лучше разовых паков.
- Сводный портрет дорожает с каждым тестом (§4 tests-monetization) — подписка снимает
  трение «каждый апдейт портрета за полную цену».
- LTV рекламного трафика: подписка выравнивает окупаемость когорт против разовых покупок.
- Контраргумент, который надо честно взвесить: у продукта пока нет доказанного
  повторного использования (Э9 не запущен) — подписка до ретеншна может оказаться
  преждевременной оптимизацией.

## Развилка 1 — что даёт подписка

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| A. Месячный грант кредитов | $X/мес → N кр/мес на тот же баланс | Минимум изменений: ledger уже умеет grant/spend; вся ценовая логика (95/5/145) не трогается | Психологически это «абонемент на кредиты», не подписка на продукт; неиспользованные кредиты — вопрос переноса |
| B. Безлимит контента | $X/мес → разборы/чат/портрет без списаний | Простая ценность «всё включено» | Ломает единую модель «любой разбор — 95»; косты LLM не ограничены сверху; каннибализация паков |
| C. Гибрид | Безлимит разборов тестов + грант кредитов на чат/портрет/фото | Балансирует косты (разбор дешёвый, ~$0.03–0.06) и ценность | Сложнее объяснить и реализовать |

Рабочая гипотеза для обсуждения: **A** как первый шаг (минимальный код, честная экономика),
с бонусом подписчику (например, +15% кредитов против пака той же цены и/или скидка на
обновление портрета). B/C — только после данных о частоте использования.

## Развилка 2 — техника

- **Провайдер**: Polar поддерживает подписки (сейчас используем one-time checkout в
  `credits-polar-checkout`). Нужен webhook жизненного цикла (created / renewed /
  canceled / past_due) — аналог `unloop-polar-webhook`, но с периодикой.
- **Ledger**: вариант A ложится в существующий `credits_ledger` новым kind
  (`grant_subscription`, идемпотентный ключ `sub:{subscription_id}:{period_start}`).
  Отдельная таблица `looplore_subscriptions` (user_id, provider_sub_id, plan, status,
  current_period_end) — источник истины по статусу.
- **Entitlement-проверки**: сейчас все гейты — «хватает ли кредитов» в `credits_spend`.
  Вариант B/C добавляет второй тип гейта («активная подписка») во все спендящие
  функции — ровно поэтому A дешевле.
- **Перенос кредитов**: сгорают в конце периода / копятся / копятся с потолком.
  Влияет на p_meta грантов и на копию в кабинете.
- **Отмена и downgrade**: что происходит с балансом и купленным контентом (купленный
  контент не запирается — инвариант кредитной экономики, держим и для подписки).
- **Цены/планы**: минимум один план на старте; годовой — потом. Сетку строить от
  фактического ARPPU кредитной экономики, не из головы.
