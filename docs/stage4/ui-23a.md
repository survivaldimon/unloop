# Этап 4, поток C — UI-часть решения 2.3A: перемешивание вариантов и укорачивание ассертива

Ветка: `stage4/ui-23a` от свежего main (`3b67b54`; в постановке потока указан
`b2b74bf`, но поверх него в main уже лежал docs-коммит отчёта этапа 3 — взят
буквально свежий main, дельта docs-only). Прод не трогался, деплоя нет,
ENGINE_VERSION и golden-фикстуры не менялись.

Проблема (аудит §6.4, рецензия флагмана `docs/tests-content-review.md` §5):
у text_conflict_communication ассертивный вариант в каждом из 20 вопросов
(а) всегда последний — порядок ответов в источнике = порядок факторов,
(б) длиннейший — замер до правки: последний и самый длинный в 20/20, перекос
1.6–4.04× против среднего остальных, (в) написан «терапевтическим скриптом».
К третьему вопросу тест меряет «знаю ли я правильный ответ», а не поведение.

## Решения основателя (раунд 1, 05.08.2026 — все рекомендованные варианты)

1. **Кого перемешивать**: все `answer_factor`-тесты (критерий по типу
   скоринга). Сегодня это единственный флагман — он же единственный
   сценарный; 18 ликерт/биполярных шкал («никогда … всегда») не перемешиваются
   по построению, будущие сценарные тесты подхватятся автоматически.
2. **Стабильность порядка**: детерминированный сид `session_id + question_id`.
   Back / перезагрузка / резюме показывают тот же порядок; retake минтит новую
   сессию (`resetTestSession`) — порядок пересдаётся; у разных посетителей
   порядок разный, чужой скриншот позиций не выдаёт.
3. **Объём укорачивания**: худшие 7 вопросов по перекосу — q12 (4.04×),
   q1 (4.02×), q16 (3.5×), q13 (3.45×), q9 (3.34×), q5 (3.21×), q15 (3.19×).
4. **Тон**: «живой + короткий» — 1–2 фразы как реально пишут в мессенджере,
   без терапевтического скрипта, суть ассертива сохранена (чувство/граница/
   предложение без наезда), цель ~60–90 знаков RU.

Раунд 2 (эталон стиля): до/после на q12, q1, q16, q9 утверждены, остальные
три (q13, q5, q15) — «добивай в том же тоне» без отдельного круга.

## Что сделано

### Перемешивание при показе (`src/tests/shuffle.ts` + `TestRunner`)

`displayAnswers(test, question, sessionId)`: для `answer_factor` — Fisher–Yates
поверх копии `question.answers` на PRNG mulberry32, сид FNV-1a от
`${sessionId}:${question.id}`; для остальных скорингов возвращает исходный
массив без изменений. Врезка — `QuestionCard` получает готовый порядок пропсом
(`TestRunner.tsx`), буквы а/б/в/г и анимация привязаны к позиции показа.
Скоринг не тронут: движок ищет ответ строго по id (`engine.ts:71,87,114`),
что подтверждено зелёным `tests:verify` до и после.

### Укорачивание ассертивных ответов (только `text`, id/score не менялись)

Конвенция этапа 0: `tools/tests-import/overrides/text_conflict_communication.json`
и зеркало `src/content/tests/text_conflict_communication.json` правятся
синхронно в одном коммите (конвейер `tests:build` в воркдереве не запускается —
staging `out/` не версионируется). Сверка «оверрайд == канон» по всем девяти

## Проверка (05.08.2026, vite dev в воркдереве)

- `npm run tests:verify` — 76 кейсов, 0 расхождений, до и после правок
  (тексты в фикстуры не входят, числа не менялись).
- `npm run build` — зелёный (tsc + vite, 177 модулей + OG-страницы 19 тестов).
- Живой проход флагмана в браузерном превью, наблюдавшиеся порядки (позиции
  а/б/в/г — фактический показ; в исходнике ассертив везде 4-й):

| Экран | Порядок показа | Ассертив |
|---|---|---|
| q1, первый показ | агрессия / пассив / **ассертив** / избегание | 3-й |
| q2 | избегание / агрессия / **ассертив** / пассив | 3-й |
| q20 | **ассертив** / агрессия / избегание / пассив | 1-й |
| q1 после Back | тот же порядок, выбор подсвечен | стабильно |
| q2 после перезагрузки | тот же порядок (резюме той же сессии) | стабильно |
| q1 после retake | пассив / агрессия / избегание / **ассертив** | пересдан |

- RU/EN дают один и тот же порядок (сид не зависит от языка), буквы а/б/в/г
  следуют позиции показа.
- Целостность скоринга: клик по «Люблю тебя тоже…» на **первой** позиции q20
  записал id `20d` — id следует за ответом, не за позицией. Итог прохода
  (Прямота 35 / Агрессия 25 / Избегание 20 / Пассив 20 → «Зависит от
  человека») сверен с независимым пересчётом по канону — совпадение полное,
  включая правило этапа 2 (top1 35 при diff12 10 < 15 → mixed).
- Скриншот перемешивания будет добавлен отдельным коммитом: панель браузера
  на момент прогона не отображалась у основателя, кадры не компоновались —
  функциональные проверки выше сняты по DOM.
