# Этап 4, поток A — типология v2 «Личные границы и угождение»

Дата: 05.08.2026. Ветка `stage4/boundaries-v2` (от main 3b67b54), ждёт мержа
координатором этапа 4. Закрывает вопрос №8 коридор-дока
(`docs/tests-target-distributions.md` §8): 48 вопросов, 6 факторов — и всего
3 исхода, из них фолбэк у 56.8% людей (после этапа 2; до него — 79.5%).

## Решения основателя (все — через AskUserQuestion, три раунда 05.08.2026)

Раунд 1 — рамка:

1. **Архитектура**: гибрид «полюса + механизмы середины» (а не чистая
   типология механизмов и не сетка 2×2). Полюса остаются, середина режется
   по ведущему механизму.
2. **Ясность границ** (q41–q48, измерялась и не влияла): включить двояко —
   гейт в формулу мастера + именная ветка «Туман».
3. **Старые три профиля**: сохранить, точечные правки WHY; «Строитель
   границ» остаётся именем фолбэка.
4. **Тон и имена**: каталожный стиль — короткие образы, тёплое «ты», без
   диагнозов.

Раунд 2 — состав и цифры:

5. **Состав: 7 профилей** — оба полюса + все четыре механизма + фолбэк.
6. **Имена (набор 1)**: «Радар одобрения» / The Approval Radar,
   «Тихая граница» / The Quiet Line, «Себя — потом» / Me Last,
   «Туман» / The Fog.
7. **Коридоры v2**: Удобный 20–30, Хозяин 10–18, каждый механизм 5–12,
   Строитель-фолбэк 10–20 (именной результат ≥80% людей).
8. **supportNote**: только «Радару одобрения» (страх отвержения — тема
   привязанности; остальные механизмы — навыковые дефициты).

Раунд 3 — материалы:

9. **Тексты четырёх новых профилей** (полный набор полей ru+en) — «го, как
   есть».
10. **Правки WHY старых трёх** под формулы v2 — «го».
11. **Порядок правил и ничьи**: Удобный → Хозяин → Радар(страх) → Туман →
    Тихая → Себя—потом → Радар(автономия); при равенстве слабейших опор
    выигрывает более раннее правило — «ок».

## Правила v2 (финальные, после калибровки)

Селектор — `tools/tests-import/fixes/boundaries_people_pleasing.json`
(profileSelection, полная замена; обоснование порогов в `$note`):

| Профиль | Формула (проценты факторов) |
|---|---|
| Удобный | `угождение ≥52 И страх_отвержения ≥42` |
| Хозяин границ | `@pillars ≥52 И каждая из четырёх опор ≥37` |
| Радар одобрения | `страх ≥91` ИЛИ `автономия <18 и слабейшая из опор` |
| Туман | `ясность <21 и слабейшая` |
| Тихая граница | `ассертивность <21 и слабейшая` |
| Себя — потом | `приоритет_себя <21 и слабейший` |
| Строитель границ | фолбэк (ничего из перечисленного) |

`@pillars` — derived-среднее четырёх опор (ассертивность, приоритет себя,
автономия, ясность). «Слабейшая» — попарные сравнения `<=` с тремя
остальными опорами; ничьи разрешает порядок правил (см. решение 11).
Сетка фактора 3.125 (8 вопросов × ликерт 0–4): эффективные пороги
52→53.1, 42→43.8, 37→37.5, 91→93.8, 21→≤18.8, 18→≤15.6.
Против «отвечал всюду средне → лучший профиль» стоит гейт `@pillars ≥52`:
ровный середняк (все факторы 50) уходит в фолбэк, а не в мастера.

Пороги подобраны grid-search'ем (~28K конфигураций) по кэшу персонной
симуляции audit2 (4000 персон, seed 777); выбрана конфигурация с
минимальным запасом до краёв коридоров 0.8 п.п. и почти едиными порогами
механизмов.

## Координатору при мерже

1. **ENGINE_VERSION bump — НУЖЕН**: правила селектора изменились — те же
   ответы дают другой профиль; сохранённые результаты обязаны пересчитаться
   механикой самолечения (пересчёт при следующей платной операции).
2. Перегон golden-фикстур: для boundaries необязателен (скоринг не
   менялся, фикстуры профиль не пинуют), но безвреден в общем перегоне.
3. Деплой обеих функций (`tests-generate-report`, `tests-portrait`) — они
   тянут контент статикой; без редеплоя новые профили в разборы не попадут.
4. Свести статусы: шапка `tests-target-distributions.md` (строка «три
   открытых вопроса»), `tests-quality-audit.md` §7 — №8 закрыт этим
   пакетом.
5. Прод-смоук: пройти тест с перекошенными ответами (например, всё
   «против себя» при высокой ясности) и сверить профиль с локальным
   расчётом.

## Грабли (зафиксировано)

- `apply-fixes.mjs --check` ложно краснеет на свежем Windows-чекаута:
  скрипт пишет LF, `core.autocrlf=true` выдаёт CRLF, `.gitattributes` нет —
  на нетронутом воркдереве «дрейфуют» все 19 файлов. Это артефакт EOL, не
  семантический дрейф (после обычного прогона apply-fixes — чисто).
  Предложен отдельный фикс (чип: нормализация EOL в --check либо
  .gitattributes).
- `tools/tests-audit/out/` git-ignored и в свежем воркдереве отсутствует —
  `audit2.mjs` падает на записи отчёта; лечится `mkdir -p` перед прогоном.
