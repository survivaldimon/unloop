# Этап 4, поток D — гигиена: порог полноты, детектор straight-line, блокирующий CI

Дата: 05.08.2026. Ветка `stage4/hygiene` (воркдерево от main 3b67b54), ждёт
мержа координатором по «го». Закрывает из `docs/tests-quality-audit.md`:
§1 «частичные ответы принимаются молча» и «answered считает мусорные id»,
§5 «нет защиты от мусорных ответов», §7 пункт 8 (линт → блокирующий), пункт 10
частично (L0/L0.5/L3 в CI), пункт 13 частично (детектор straight-line).
Из спеки робота (`docs/tests-spec-and-robot.md`) закрыт Р1 целиком.

Важное свойство пакета: **деньги, идемпотентность, кэш и ENGINE_VERSION не
тронуты ни на байт**. Порядок cache → gate → spend → generate → writeback обеих
функций прежний; все новые проверки стоят ДО credits_spend и могут только
отказать до списания, но не изменить ни ключи, ни суммы. Движок меняет только
подсчёт `answered` (не участвует ни в баллах, ни в профилях; SPA поле не
использует, golden-фикстуры его не фиксируют).

## Решения основателя (05.08.2026, все — рекомендованные варианты)

| # | Развилка | Решение |
|---|---|---|
| 1 | Порог полноты платного разбора | **≥80%** честно отвеченных вопросов (`Math.ceil(0.8 × questions)`) — переживает добавление вопросов в v2 тестов |
| 2 | Поведение при недоборе | **409 `{error: "incomplete_answers", answered, required}` ДО спенда** (фронт показывает общий фейл — UI этот путь создать не может) |
| 3 | Мусорные answerId | **Честный подсчёт в движке**: ответ засчитан, только если answerId существует в вопросе (engine.ts, одна строка) |
| 4 | Портрет | **Тот же порог для участия сессии в композиции**: сессия <80% пропускается с фолбэком на более старую полную того же теста; если тестов <3 — честный 403 gate |
| 5 | Детектор straight-line: действие | **Пометка в фид + лог, покупку не блокировать**: `response_quality` в фиде разбора и в записи tests_taken портрета + полстроки семантики в оба системных промпта + `console.log("response_quality_flag", …)` для L5-дрейфа |
| 6 | Детектор: формула | **modal ≥ 0.9 ∨ variance ≤ 0.01 ∨ extremes ≥ 0.95** по валидным ответам (modal — доля самой частой позиции ответа; variance — дисперсия нормированного 0..1 балла; extremes — доля крайних; у answer_factor осмыслен только modal) |
| 7 | Состав блокирующего CI | **tests:audit + tests:lint + tests:feed-invariants** (плюс уже стоявший tests:verify) |
| 8 | Классы линта | **A + B + E блокируют** с baseline (B=1 принятое исключение social_battery q16/q34); C/D остаются отчётными by design |

Калибровка формулы детектора на golden-фикстурах и синтетике (метрики
считались прототипом, затем закреплены L3-инвариантом): all_min / all_max
(modal 1.0, var 0, extremes 1.0), middle (modal 1.0, var 0) и «90% одной
кнопки» — ловятся; зигзаг мин/макс — ловится по extremes; ladder (modal 0.2)
и «шумный скошенный к согласию человек» (modal ≈0.45, var ≈0.03) — чистые.
На тестах С реверсами честный экстремал не страдает (позиции переворачиваются
на реверс-пунктах — modal падает); на тестах без реверсов
(toxic/fomo/attachment/LL до v2) аквиесценция и честность неразличимы by
design — поэтому пометка, а не отказ.

## Что изменилось

**`src/tests/engine.ts`** — `answered` считает только answerId, существующие в
вопросе. Скоринг/правила/ENGINE_VERSION (=2) не тронуты, фикстуры не
перегенерировались (поле в них не входит).

**`supabase/functions/_shared/response-quality.ts` (новый, чистый)** —
`COMPLETENESS_THRESHOLD = 0.8`, `minAnsweredRequired(test)`,
`analyzeResponsePattern(test, answers)` (метрики + вердикт), константы порогов,
`RESPONSE_QUALITY_WARNING` (единая строка предупреждения обоих фидов). Без
Deno/npm-зависимостей — робот компилирует его esbuild'ом вместе с билдерами.
В комментарии зафиксировано: позиция ответа = индекс в `question.answers`;
если приедет перемешивание вариантов (UI-часть 2.3A), modal-метрике нужен
порядок, который видел пользователь (variance/extremes переживают перемешивание
как есть).

**`_shared/report-payload.ts`** — `buildPayload` добавляет
`response_quality: <warning>` только у сработавших сессий (поле рядом с
`answered`).

**`_shared/portrait-input.ts`** — запись tests_taken несёт то же поле у
сработавшей сессии.

**`tests-generate-report/index.ts`** — после пересчёта и `no_answers`: порог
`recomputed.answered < minAnsweredRequired(test)` → 409 `incomplete_answers`
(до mismatch-лога, writeback и спенда); лог `response_quality_flag`; в
SYSTEM_BASE полстроки: предупреждение = механический паттерн, смягчить
уверенность, опираться на скелет профиля, можно бережно назвать — не обвинять.

**`tests-portrait/index.ts`** — фильтр композиции: сессия с честным
`answered < 80%` пропускается (фолбэк на более старую полную — та же ветка,
что у пустых answers); лог `response_quality_flag` в цикле пересчёта; в
SYSTEM_BASE полстроки: помеченный тест взвешивать легко, не строить на нём
throughlines/противоречия.

**`tools/tests-audit/audit.mjs`** — блокирующий: проблемы вне
`audit-baseline.json` → exit 1 (устаревшие записи baseline печатаются как
напоминание); `--l0` пропускает Монте-Карло (CI-режим, секунды вместо ~5 мин);
mkdir для `out/` (в свежем чекауте CI каталога нет). Baseline: 4 принятых
`missing_factor_name` sixteen_types (EI/SN/TF/JP — биполярные факторы в фиды
не ходят с этапа 3, имена были бы мёртвым контентом).

**`tools/tests-audit/lint-weights.mjs`** — блокирующий по классам A/B/E против
`lint-baseline.json` (ключи включают вес/списки вопросов — изменение принятого
места ломает ключ и требует пере-ревью); C/D отчётные. Baseline: 1 запись
(B social_battery q16/q34, семантика зафиксирована этапом 2).

**`tools/tests-audit/feed-invariants.mjs`** — +208 проверок (17 062 → 17 270):
`straight-line-marked` — пометка в фиде разбора и в tests_taken портрета стоит
ровно там, где её требует НЕЗАВИСИМЫЙ пересчёт формулы по сырому JSON (пороги
захардкожены в инварианте нарочно — дрейф констант в `_shared` будет пойман);
`answered-honest` — мусорные answerId не считаются (всё-мусор → 0, один мусор →
−1). `--v1` теперь показывает 10-й сломанный класс (у этапа 2 пометок не было).

**`package.json`** — скрипты `tests:audit` (`audit.mjs --l0`), `tests:lint`.

**`.github/workflows/ci.yml`** — после существующих build + tests:verify
добавлены три блокирующих шага: `tests:audit`, `tests:lint`,
`tests:feed-invariants`. Существующие шаги не тронуты. Замечание: esbuild для
feed-invariants приезжает транзитивно через vite (в devDependencies его нет) —
если когда-нибудь vite его уронит, CI упадёт громко, фикс тривиален.

**Доки** — статус-вставка в `docs/tests-quality-audit.md` (§7-статусы),
обновление 05.08 в `docs/tests-spec-and-robot.md` (Р1 закрыт), README
tests-audit (блокирующий набор, baseline-конвенция).
