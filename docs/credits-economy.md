# Кредитная экономика Looplore — спецификация v1

Статус: дизайн и финальные цены согласованы с основателем 27.07.2026 (разбор 95, вопрос 5, инсайт 10, вход $3.49). «Го» на launch-скоуп A+B+C получено 27.07.2026. Прод-шаги (миграции, боевые Polar-продукты, деплой) — отдельным одобрением.
Заменяет разовую оплату $14.99 (quiz-отчёт и photo read) единой кредитной экономикой.

---

## 1. Цель и принципы

- Один баланс кредитов на пользователя, работает в обеих воронках (quiz + photo).
- Дешёвый кредит, большие числа: 1 кр ≈ $0.01 по bulk-курсу.
- Экономика из трёх петель: покупка (паки) → траты (разборы, чат) → возврат (ежедневный грант + инсайт дня).
- Вход радикально ниже текущего: Mini-пак $3.49 покрывает «разбор + вопрос» (было $14.99 за разбор). Ставка на объём покупателей в экосистеме; AOV добираем Starter'ом (предвыбран на пейволле), топапами и повторными тратами. Net с Mini после комиссий Polar (~4% + 40¢) ≈ $2.95 — окупаемость либо CPA < ~$3, либо хвостом покупок. Решение основателя 27.07.
- Купленный контент не запирается: списание происходит за генерацию; готовый отчёт/ответ доступен навсегда.

Mini-пак = ровно «разбор + 1 вопрос» (95+5=100). Вопрос (5) дешевле инсайта (10) осознанно: вопросы почти бесплатны и втягивают в чат, но требуют купленного разбора. Цены действий живут в серверном конфиге — их можно менять без смены Polar-продуктов (главный рычаг тонкой настройки после запуска; баланс юзеров при этом не трогается).

## 4. Гранты и бонусы

| Грант | Сколько | Условие | Идемпотентность |
|---|---|---|---|
| Email signup | +20 | Один раз на аккаунт (шаг email в воронке) | `signup:{user_id}` |
| Ежедневный | +10 | Claim при заходе, всем с аккаунтом (включая некупивших). Пропущенные дни сгорают, накопления нет | `daily:{user_id}:{YYYY-MM-DD}` |
| Streak (v1.1) | +50 | 7 дней подряд claim | `streak:{user_id}:{N}` |
| Таймер-бонус | +25% кредитов к паку (Mini +25, Starter +250, Big +625) | Покупка в персональное 15-мин окно с первого показа пейволла | входит в grant покупки |

Free-петля работает с нуля: day 0 → +20, инсайт −10; каждый следующий день +10 → инсайт −10. Бесплатник получает инсайт ежедневно. Накопить на разбор — ~8 дней заходов подряд: осознанная retention-фича (нетерпеливые покупают за $3.49, терпеливые — прогретая база; себестоимость разбора — центы). Мониторим каннибализацию по метрикам.

## 5. Промо-механики

- Таймер гейтит **бонус, а не цену**: «в ближайшие 15 минут → +25% кредитов к паку». Окно персональное, evergreen (как текущий таймер), но эффект реальный — бонус действительно сгорает. Фейковых скидок с меняющейся ценой не делаем (dark-patterns риск в EU).
- Якорная подача Starter: ~~$19.99~~ → $9.99 «launch price» (якорь = реальная цена Big-эквивалента, подача аккуратная).
- Post-purchase апселл: сразу после первой покупки, один раз на аккаунт — Big+ 3750/$19.99.
- Comeback (v1.1): 7 дней тишины → email «сегодня двойной грант» (+20 вместо +10).
- Ручные sale-ивенты — через Polar discounts (код вводится прямо в чекауте, настраивается в дашборде Polar; процент или фиксированная сумма, лимит погашений, срок, привязка к продуктам). Кода с нашей стороны не требует.
- **Промокоды на кредиты** — наши, мимо чекаута и мимо комиссии Polar. Код → +N кредитов на баланс *залогиненного* аккаунта. См. §5.1.

### 5.1. Промокоды на кредиты

Миграция `20260727140000_promo_codes.sql`, функция `credits-promo`, поле ввода в пейволле и топ-ап модалке, плюс автоприменение из ссылки `?promo=КОД`.

Выпуск кода — из SQL-редактора Supabase:

```sql
-- код, кредиты, лимит погашений (null = без лимита), срок жизни, заметка
select credits_promo_create('TEST1000', 1000, 5, '7 days', 'launch testing');

select * from looplore_promo_stats;                     -- сколько погасили и когда
update looplore_promo_codes set active = false where code = 'TEST1000';  -- мгновенный стоп
```

Правила, зашитые в `credits_redeem_promo` (всё в одной транзакции):

- Кредиты идут **только на залогиненный аккаунт** — за кодом не стоит заказа Polar, поэтому проверка личности и есть вся защита. Ни email, ни session id в качестве адресата не принимаются.
- Один аккаунт гасит код один раз (PK таблицы погашений + идемпотентный ключ `promo:<код>:<user>` в леджере — повтор не может начислить дважды).
- Бюджет кода списывается под row lock: последний слот достаётся ровно одному.
- 10 неверных попыток в час на аккаунт — дальше `throttled`, а в UI это выглядит как «такого кода нет» (говорить про лимит = рассказывать, что он есть).
- Погашённый код — строка леджера `grant_promo`, то есть виден во всей той же аналитике, что и покупки.

Что помнить: код на N кредитов — это N/95 бесплатных разборов для каждого, кто его узнает. Публичным кодам всегда ставь `max_redemptions` и срок; `active = false` гасит утёкший код мгновенно.

С 07.08.2026 у промокода может быть **владелец**: личные реф-коды аккаунтов живут на этом же рельсе (`docs/referrals-compare.md` §6). В `credits_redeem_promo` из-за этого две дополнительные ветки, для обычных кодов безразличные: погашение **своего** кода отвечает `own_code` (и не считается неверной попыткой), а успешное погашение чужого личного кода начисляет владельцу реферальный грант — по ключу «пара аккаунтов» и под общим потолком 5 наград/30 дней. Функция `credits-promo` возвращает `referral: true/false`, чтобы событие `promo_redeem` различало код друга и кампанийный код.

## 6. UX-точки

1. **Баланс-чип** в шапке обеих воронок (виден после создания аккаунта): число + «+10» анимация при claim.
2. **Пейволл разбора** (замена текущих Teaser price-card): 3 карточки — Starter крупно/предвыбран, Mini мельче, Big; таймер-бонус +25%, «у тебя уже N кр» под карточками.
3. **Top-up модалка**: при нехватке на вопрос — один рекомендованный пак (Mini $3.49 = «ещё 20 вопросов») + ссылка «больше опций» (полная сетка). Polar overlay, без ухода со страницы.
4. **Чат по разбору**: на странице отчёта, input + история. Цена «50 кр» на кнопке. Контекст = отчёт + ответы/фото-тизер своей сессии. Ответ ~250–400 слов, стриминг не обязателен в v1.
5. **Инсайт дня**: карточка на странице отчёта/возврата. CTA «Получить инсайт (10 кр)»; claim гранта происходит автоматически при заходе (тост «+10»). Один инсайт в сутки, повторный заход в тот же день показывает тот же текст.
6. **Post-purchase экран**: «Кредиты зачислены: N (+25% если успел в окно)» → генерация разбора → внизу one-time Big+ оффер.

## 7. Аккаунты и идентичность

- Шаг email в воронке = **тихое создание аккаунта** (Supabase Auth, без пароля и без OTP-подтверждения до оплаты).
- **Правило безопасности**: тихий вход выдаётся только при создании *нового* юзера (email ранее не встречался). Если email уже существует — отправляем настоящий magic link; до подтверждения воронка продолжается анонимно, баланс не подключается. Иначе endpoint = угон аккаунта по знанию email.
- Механика тихого входа: server-side `admin.generateLink(magiclink)` → клиент обменивает `token_hash` через `verifyOtp` → сессия. Письмо не отправляется. Rate-limit обязателен.
- Magic link «продолжить на другом устройстве» — ссылка в письме с результатом + пункт в шапке.
- `unloop_sessions` / `photoread_sessions` получают `user_id`; связывание на шаге email.
- Анти-абьюз грантов: 1 email = 1 signup-грант; daily только аутентифицированным; троттлинг диспозабл-доменов — позже, если появится абьюз.

## 8. Данные (Supabase)

```sql
-- Баланс: кэш в аккаунте, истина в ledger
create table credit_accounts (
  user_id uuid primary key references auth.users(id),
  balance int not null default 0 check (balance >= -100000),
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create table credit_ledger (
  id bigint generated always as identity primary key,
  user_id uuid not null references auth.users(id),
  delta int not null,                     -- + начисление, − списание
  kind text not null,                     -- purchase | bonus_timer | grant_signup | grant_daily | grant_streak
                                          -- | spend_report | spend_photo | spend_question | spend_insight
                                          -- | refund | adjust
  ref text,                               -- order_id / session_id / question_id / date
  idempotency_key text not null unique,
  meta jsonb,
  created_at timestamptz default now()
);
```

- RPC `credits_spend(p_user, p_amount, p_kind, p_key, p_ref)` — атомарно: `insert ledger` + `update balance` в одной транзакции, отказ при нехватке. SECURITY DEFINER, вызывается только из edge functions (service role). Повтор с тем же `p_key` — no-op с текущим балансом (безопасные ретраи генерации).
- RPC `credits_grant(...)` — аналогично для начислений.
- Баланс может уйти в минус только через `refund/adjust` (возврат пака после частичной траты) → траты блокируются до пополнения.
- Конфиг цен/паков — один источник: `supabase/functions/_shared/credits-config.ts`, импортируется и фронтом (через общий src), и функциями. Никаких цен, размазанных по 6 файлам, как сейчас.

## 9. Polar-интеграция

- 4 новых one-time продукта (Mini/Starter/Big/Big+), sandbox → prod, ID в Vault: `POLAR_PACK_*_ID`.
- Checkout (новая функция `credits-polar-checkout`): auth-юзер, `metadata: {user_id, pack_id, bonus_eligible}`. Право на таймер-бонус фиксируется server-side (дедлайн окна храним в БД при первом показе пейволла), вебхук проверяет по нему, а не по слову клиента.
- Вебхук `order.paid` → `credits_grant(pack + бонус)`, `idempotency_key = order:{order_id}`. Meta CAPI Purchase (value = цена пака) — как сейчас.
- Refund-вебхук → отрицательный `adjust`. Политика: неиспользованные паки возвратны 14 дней (EU), потраченные кредиты — нет; waiver на мгновенную поставку цифрового контента при первой трате.

## 10. Spend-гейты (миграция с paid_at)

- `unloop-generate-report` / `photoread-report`: вместо проверки `paid_at` → `credits_spend(95, 'spend_report'|'spend_photo', key='report:{session_id}')`. Ключ на сессию = повторная генерация той же сессии бесплатна (ретраи, повторное открытие).
- **Grandfathering**: если у сессии стоит `paid_at` (старые покупки) — доступ без списания, навсегда.
- Новая функция `looplore-chat`: спенд 5/вопрос, `key='q:{question_id}'`, история в таблице `chat_messages`.
- Новая функция `daily-insight`: claim (+10, идемпотентен на дату) выполняется при заходе; спенд 10 — при запросе инсайта; результат кэшируется в `daily_insights (user_id, date unique)`.
- Флаг `CREDITS_ENABLED` (Vault/env): off = старый пейволл и старая логика целиком. Мгновенный откат.

## 11. Аналитика

PostHog: `paywall_view`, `pack_select`, `checkout_open`, `purchase {pack, value, bonus}`, `credits_spend {kind}`, `balance_zero`, `topup_view`, `topup_purchase`, `chat_question`, `daily_claim`, `insight_view`, `upsell_view`, `upsell_purchase`, `promo_redeem {credits, source}`.
Meta: `InitiateCheckout`, `Purchase` (value = пак). AOV в Meta станет переменным — это ок, событий Purchase станет больше (top-ups), сигнал для оптимизации плотнее.
Ключевые метрики запуска: конверсия пейволл→покупка (vs текущая), микс Mini/Starter/Big в первых покупках, доля top-up в выручке, D1/D7 return (claim), вопросов на покупателя, каннибализация разборов дневным грантом.

## 12. Легал

- Terms (EN+RU): секция Credits — кредиты не валюта, не переводятся, потраченные не возвращаются, неиспользованные паки — refund 14 дней, waiver мгновенной поставки, право менять цены в кредитах с уведомлением.
- Координация с сессией локализации: новые строки UI + правки Terms идут через неё.

## 14. Deploy-чеклист (прод-шаги — только с отдельного «го»)

1. Миграция: `supabase/migrations/20260727120000_credits_foundation.sql` в прод-проект (SQL editor / `supabase db push`).
2. Polar-продукты: `POLAR_ACCESS_TOKEN=… node scripts/polar-credits-setup.mjs` (sandbox), потом с `POLAR_ENV=production`; полученные id — в Vault (`POLAR_PACK_MINI/STARTER/BIG/BIGPLUS_ID`).
3. Деплой функций: новые `credits-auth`, `credits-polar-checkout`, `looplore-chat` (verify_jwt по умолчанию) + обновлённые `unloop-polar-webhook` (как раньше, `--no-verify-jwt`), `unloop-generate-report`, `photoread-report`.
4. Supabase Auth: подключить кастомный SMTP (Resend) — иначе magic-link письма существующим юзерам упираются в лимит 2/час; проверить Site URL.
5. Включение: Vault `CREDITS_ENABLED=true` + фронт `VITE_CREDITS_ENABLED=true` → build+deploy. Флаги переключать парой.
6. Smoke в sandbox: покупка каждого пака, бонус в окне/вне окна, чат-вопрос, retry вопроса, grandfathering старой paid_at-сессии, top-up из чата.
7. Откат: оба флага в false (Vault мгновенно, фронт — redeploy) — возвращает старую $14.99-экономику целиком.
8. Отдать сессии локализации: строки `src/lib/creditsCopy.ts` (RU-черновик внутри) и секцию Credits в Terms (EN+RU).

Промокоды (§5.1) — отдельным шагом: миграция `20260727140000_promo_codes.sql` + деплой `credits-promo` + фронт. Проверка после деплоя: выпустить код на 1000 кр с лимитом 1, пройти воронку до пейволла, применить — баланс должен вырасти, повтор того же кода тем же аккаунтом должен дать «уже использовал».

## 15. Дефолты, принятые без отдельного обсуждения

- Название валюты: «кредиты» (брендинг — отдельным решением, вместе с локализацией).
- Кредиты не сгорают (v1); сгорающие промо-бонусы — v2.
- Чат: вопрос ≤ 500 символов, ответ ~120–220 слов (при цене 5 кр длинные эссе не нужны), контекст — одна сессия/разбор + последние 6 обменов.
- Инсайт дня персонализируется тем, что есть: полный отчёт → по нему; только тизер/паттерн → по ним.
- Photo-воронка сейчас EN-only — кредитные строки для неё сразу EN, RU придёт с локализацией.
