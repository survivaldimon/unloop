# tests-audit — зародыш робота-тестировщика

Скрипты независимого аудита качества тестов (31.07.2026, ветка
`claude/test-quality-analysis-47ec2e`). Это НЕ замена `tests-import/verify-engine.mjs`
(движок против golden-фикстур) — это следующие уровни проверки: структура данных,
геометрия правил, распределение профилей, фид портрета. План развития —
`docs/tests-spec-and-robot.md`; находки — `docs/tests-quality-audit.md`.

## Скрипты

```bash
node tools/tests-audit/audit.mjs               # L0+L2: структурный аудит + Monte Carlo (медленный, ~5 мин)
node tools/tests-audit/audit2.mjs              # L2: персонная симуляция (4000 коррелированных «людей» на тест)
npm run tests:portrait-sim                     # L3: сколько противоречий доезжает до модели портрета (v1 против v2)
npm run tests:feed-invariants                  # L3: инварианты обоих LLM-фидов на фикстурных сессиях (exit ≠ 0)
npm run tests:feeds -- --impl shared           # L3: снапшоты всех фидов (158 файлов) в out/feed-snapshots/
```

- `audit.mjs` — консистентность index.json, дубликаты id, локализация, веса-сироты,
  правила: ссылки на несуществующие профили/факторы, непокрытые byTop/combo,
  профили без единой ссылки; равномерно-случайная симуляция достижимости.
- `audit2.mjs` — честная модель респондента: латентные черты на фактор,
  reversed-aware, шум + аквиесценция; выдаёт распределение профилей, долю
  fallback и список профилей, недостижимых ни пробами, ни персонами.
  Внутри — reversed-aware пробы: consistent_0..1, «один фактор высокий».
- `portrait-feed.mjs` — персоны на реальном движке (компилируется esbuild'ом),
  фид строится и старой логикой (`reference-feeds-v1.mjs`), и живым
  `_shared/portrait-input.ts`; печатает, какая доля шкал с межтестовым
  расхождением ≥30 доезжает до модели в каждой версии.
- `feed-snapshot.mjs` — детерминированные снапшоты пейлоадов обеих функций на
  golden-фикстурах (19 тестов × 4 кейса × 2 языка + 3 композиции портрета);
  `--impl reference` строит их старой логикой, `--compare A B` сверяет
  байт-в-байт (так доказан паритет выноса в _shared: 158/158).
- `feed-invariants.mjs` — L3-инварианты фидов: направление quote_candidate по
  фактору, отсутствие нулевых факторов/полюсных абсолютов у биполярных, полюса
  только осями, порог ≥2 вопросов на вклад, «громкие противоречия обязаны
  попадать в фид», непустые секции, токен-бюджеты. `--v1` гоняет те же проверки
  по логике этапа 2 (демо того, что было сломано; exit 0).

Отчёты пишутся в `out/` (git-ignored). Аудиты L0/L2 (`audit.mjs`, `audit2.mjs`,
`lint-weights.mjs`) пока держат собственную реплику движка — при изменении
`src/tests/engine.ts` сверять; L3-скрипты реплики не имеют, они компилируют
настоящий движок и настоящие билдеры фидов.

## lint-weights.mjs (L0.5)

```bash
node tools/tests-audit/lint-weights.mjs
```

Направленный линт весов против `tools/tests-import/scale-registry.json`:
A — знак против ключёвки пункта; B — противоречия знаков внутри фактора;
C — «вклеенные хвосты» (пара шкала=вес на ≥6 вопросах); D — тесты без
отрицательных весов; E — инвентарь полюсных примесей в тестах состояния.
Замечания к чтению: у sixteen_types находки C/D — by design (полюсные веса
равномерны по построению); A-подозрения — материал для проверки, не приговор
(правило этапа 2: флаг → проверка по смыслу → правка). Пока веса не починены,
линт отчётный (exit 0); после этапа 2 фиксируется baseline и линт становится
блокирующим.
